# Lossless Analyzer

Десктопное приложение для проверки того, является ли аудиофайл настоящим
lossless. Ищет «кирпичную стену» и мягкие срезы в спектре — след lossy-кодека
(MP3/AAC) или ресемплера, пересохранённого во FLAC/WAV, проверяет стабильность
среза во времени и определяет апскейлы hi-res из CD-источника.

![Вердикт FAKE LOSSLESS, пример окна](docs/screenshot.png)

## Возможности

- Загрузка WAV, FLAC, AIFF, OGG, MP3, M4A/ALAC, AAC и других форматов
  (список файлов, диалог или drag-and-drop).
- Устойчивость к путям с эмодзи и не-ASCII символами: если libsndfile не
  может открыть/прочитать файл, он автоматически декодируется через ffmpeg.
- Усреднённый по файлу спектр в дБFS с отметками частоты Найквиста и среза.
- Спектрограмма с цветовой картой `magma` и разметкой найденного среза.
- Анализ во времени: для громких кадров считается верхняя граница спектра;
  медиана и p10–p90 показывают, постоянен ли срез (VBR, монтаж, фильтрованные
  фрагменты).
- Мощность каналов суммируется, поэтому противофазный ВЧ-контент не исчезает
  при моно-даунмиксе.
- Оценка эффективной разрядности: 16-битный мастер в 24-битном PCM-контейнере
  помечается отдельно.
- Автоматический вердикт с цветовой индикацией и уверенностью:
  - `TRUE LOSSLESS` — резких срезов нет, энергия доходит до Найквиста;
  - `FAKE LOSSLESS (UPSCALE)` — найден обрыв спектра (включая «мягкие»
    апскейлы после ресемплера);
  - `INCONCLUSIVE` — тихий/тёмный материал, данных недостаточно;
  - `LOSSY SOURCE` — исходный контейнер сам по себе сжат с потерями.
- Оценка вероятного исходного формата по частоте среза
  (например, «MP3/AAC ≈ 192 кбит/с» или «апскейл с 44.1 кГц»).
- Экспорт отчёта в PNG/PDF: вердикт, метаданные, оба графика.
- Фоновый анализ: интерфейс не замерзает даже на длинных файлах.

## Установка

Нужен Python 3.10+.

```powershell
cd G:\music\analyzer
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

На Linux/macOS активация окружения: `source .venv/bin/activate`.

Важно: с NumPy 2 нужен matplotlib 3.9 или новее. Если в системе уже стоит
старый matplotlib 3.7, обновите его (`pip install -U "matplotlib>=3.9"`),
иначе при запуске будет ошибка про `numpy.core.multiarray`.

### ffmpeg (опционально)

WAV/FLAC/MP3/OGG читаются напрямую через `soundfile`. Для M4A/ALAC/AAC/WMA
программа автоматически декодирует файл через `ffmpeg` во временный WAV.
Тот же fallback включается, если libsndfile падает на пути с эмодзи или
спецсимволами (например, `Внутренняя ошибка psf_fseek`). Если ffmpeg не
установлен, эти форматы и проблемные пути не откроются — остальные продолжат
работать.

- Windows: `winget install Gyan.FFmpeg` (или скачать с ffmpeg.org);
- macOS: `brew install ffmpeg`;
- Linux: `sudo apt install ffmpeg`.

## Запуск

```powershell
python main.py
```

Добавьте файлы кнопкой «Добавить файлы», через `Ctrl+O` или перетащите их в
окно. Анализ выполняется по очереди; клик по файлу в списке показывает его
результат. `Ctrl+E` — экспорт отчёта, `Delete` — убрать файл из списка.

## Как это работает

1. **Опорный уровень.** Усреднённый спектр (БПФ с окном Ханна, потоковое
   чтение) переводится в дБ относительно полосы 1–4 кГц. Для каждого канала
   считается мощность, затем каналы усредняются: это не теряет противофазный
   ВЧ-контент, который исчез бы при простом моно-даунмиксе.
2. **Сглаживание.** Медианный фильтр и скользящее среднее убирают узкие
   тональные пики, оставляя форму огибающей.
3. **Поиск обрыва.** Для частот от 9.5 кГц до (Найквист − guard) считаются:
   - перепад между полосами до и после кандидата (широкий и локальный);
   - крутизна обрыва (доля перепада, приходящаяся на ±400 Гц);
   - разброс уровня на «полке» после среза.
   Кандидат проходит, если перепад ≥ 22 дБ, локальный перепад ≥ 12 дБ,
   обрыв достаточно крутой, а полка плоская. Положение уточняется по
   максимальному градиенту.
4. **Мягкий срез.** Если резкой стены нет, ищется устойчивая низкоуровневая
   полка у верхней границы и заметный спад перед ней. Так ловятся SRC-апскейлы,
   у которых фильтр растянул срез на несколько кГц, и срезы в 48-кГц
   контейнерах. Учитывается частота Найквиста: если в 48-кГц файле энергия
   кончается на 20–22 кГц, это подозрительно.
5. **Проверка во времени.** Для каждого громкого кадра спектрограммы
   находится верхняя граница (последняя частота не ниже −55 дБ относительно
   полосы 1–4 кГц). Медиана и p10–p90 сравниваются с найденным срезом.
   Стабильный срез повышает уверенность; большой разброс или энергия выше
   среза в заметной доле кадров добавляет предупреждение о VBR/монтаже.
   Если средний спектр доходит до Найквиста, а в части кадров граница заметно
   ниже, вердикт становится `INCONCLUSIVE`, а не `TRUE LOSSLESS`.
6. **Вердикт.** Без обрыва проверяется энергия у верхней границы диапазона:
   есть энергия — lossless, тихо/тёмно — inconclusive. Для целочисленного PCM
   дополнительно проверяется сетка квантования: 16-битные сэмплы в 24-битном
   контейнере помечаются как эффективная разрядность ≈16 бит.

Частота среза переводится в оценку битрейта по таблице, откалиброванной по
LAME: 128 кбит/с ≈ 16.6 кГц, 192 ≈ 18.8 кГц, 320 ≈ 20.2 кГц (для 44.1 кГц).
Оценка приблизительная: у AAC и разных версий кодеков срезы отличаются.

## Ограничения

- Настоящий lossless, который специально отфильтрован (лоу-фай, «тёплый»
  мастер без ВЧ), может быть помечен как fake — резкий срез есть резкий срез.
- Очень тёмный или тихий lossless без выраженных ВЧ даёт `INCONCLUSIVE`.
- Эффективная разрядность определяется только для «чистого» целочисленного
  PCM: после ресемплинга, фильтрации или float-обработки сетка квантования
  может не читаться. 16 бит в 24-битном контейнере — предупреждение, не
  доказательство апскейла.
- Программа не доказывает lossless-происхождение — она ищет характерные
  артефакты сжатия. Намеренный lowpass и фильтрованный фрагмент могут дать
  `FAKE` или `INCONCLUSIVE`.
- Длинные файлы читаются целиком (потоково), поэтому анализ может занять
  время; количество кадров для графиков ограничено, чтобы память не росла.
  Анализ во времени использует те же ограниченные кадры, поэтому очень
  короткий срез между ними может быть пропущен.
- Для файлов короче ~0.05 с анализ невозможен.

## Тесты

```powershell
python -m unittest discover -s tests -v
```

Тесты используют синтетические файлы: настоящий широкополосный сигнал,
жёсткий срез на 18 кГц, мягкие срезы на 44.1/48 кГц, естественный спад,
апскейл 44.1 → 96 кГц, реальное MP3 во FLAC, противофазное стерео,
частично фильтрованный файл, 16 бит в 24-битном контейнере, а также пути с
эмодзи и fallback через ffmpeg (если в системе есть ffmpeg с нужными кодеками).
